# Contributing

Thanks for helping keep this list useful and honest.

## What belongs here

A tool qualifies if it is **all four** of:

1. **Open source** with a public repository.
2. **Self-hostable** and **free to start** (a paid cloud tier is fine, but there must be a genuine free/self-hosted path).
3. **Actively maintained** (a release or meaningful commit activity within the last ~12 months).
4. **Genuinely useful for automation** — workflow, AI-agent, orchestration, scraping, or RPA.

Marketing-only projects, abandoned repos, and closed-source SaaS don't fit.

## How to add a tool

1. Fork and edit `README.md`.
2. Put the tool in the section that matches the **decision a user is making**, not just its tech.
3. Use this format so the star badge stays live:

   ```markdown
   - **[Name](https://github.com/OWNER/REPO)** ![](https://img.shields.io/github/stars/OWNER/REPO?style=flat&label=%E2%AD%90&color=444) — one honest sentence on what it is and when to reach for it.
   ```

4. Keep descriptions to one sentence, neutral, and specific about *when to use it* — no superlatives.
5. Open a PR explaining why it earns a place (and, if it's crowded, what it beats).

## Descriptions

Say what makes the tool *different*, not that it's "powerful" or "easy." Compare it to the obvious alternative in the same section when you can.
